# Methodology

This document records the metadata process used to turn AI-generated RGBA yarn
strips into the same library/runtime shape consumed by the existing fabric
studio and Blender pipeline.

## Baseline System Contract

The existing app expects processed yarns to enter the library as:

```text
yarn_library/<yarn_id>/
  rgba.png
  input_thumb.jpg
  metadata.json
```

When imported into the current project, the backend copies `rgba.png` to:

```text
runtime/yarn_assets/<asset_id>/rgba.png
runtime/yarn_assets/<asset_id>/asset.json
runtime/yarn_assets/<asset_id>/pbr/...
```

The important handoff field is:

```text
asset.bandMeta.blender
```

The render pipeline projects `bandMeta.blender` into Blender modifier sockets:

```text
Material N Image Width Px
Material N Texture Scale U
Material N Arc 1 V Min
Material N Arc 1 V Max
Material N Arc 2 V Min
Material N Arc 2 V Max
Scanner Pixels Per BU
```

For scanned yarns this metadata is generated by yarnseamless and refined by the
current scanned-yarn detector. For AI yarns we need a separate derivation.

## Why The Scanned Detector Was Not Enough

The current scanned detector, `detect_bands(alpha)`, is designed for real scan
exports. It uses a row-density profile based on alpha support and selects a
core using FWHM-style density thresholds. That works well when the scan has:

- real scanner scale,
- a long yarn strip,
- a relatively clear dense body,
- halos that behave like scanned fibers.

The AI generated images violated several of those assumptions:

- The generated images are short strips, around `2752-2816 px` wide.
- They are tall, `1536 px`, with large transparent/low-alpha areas.
- Loose fibers can be very long but sparse.
- The original AI `d_band` did not capture the full loose fiber support.
- The scanned FWHM detector sometimes expanded the core into what should have
  been Arc 2/halo.

That last point is the most important. If Arc 1 core is too wide, Blender maps
the dense core across too much of the strand profile. Arc 2 then receives a
small or misaligned V interval, so fiber detail appears missing.

## Current AI-Specific Algorithm

The AI process deliberately separates dense core detection from loose support
detection.

### 1. Load Source RGBA

Use the PNG as source of truth for dimensions and alpha:

```text
image_width_px, image_height_px = rgba.size
alpha = rgba[..., 3]
```

The source `measurements*.json` is retained in `ai_sanity_check`, but it does
not drive final bands.

### 2. Dense Core For Arc 1

Arc 1 should represent the dense yarn body, not the whole fuzzy silhouette.

Current detector:

```text
CORE_ALPHA_THRESHOLD = 224
CORE_DENSITY_FRACTION = 0.95

row_density[y] = mean(alpha[y, :] > CORE_ALPHA_THRESHOLD)
peak = max(row_density)
core = largest_contiguous_run(row_density >= peak * CORE_DENSITY_FRACTION)
```

Fallback thresholds are used only if that fails:

```text
224 -> 192 -> 160 -> 127
```

The final core is inclusive:

```text
core_height_px = core_bottom_y - core_top_y + 1
```

### 3. Loose Support For Arc 2

Arc 2 should cover the visible loose fiber silhouette around the dense core.
This is intentionally looser than Arc 1.

Current detector:

```text
ARC2_ALPHA_THRESHOLD = 5
ARC2_ROW_DENSITY = 0.02

support[y] = mean(alpha[y, :] > ARC2_ALPHA_THRESHOLD) >= ARC2_ROW_DENSITY
```

Starting from the dense core, walk upward and downward while the support mask
stays contiguous:

```text
outer_top = first contiguous supported row above core_top
outer_bot = last contiguous supported row below core_bottom
```

The Arc 2 source extents are:

```text
fiber_top = [outer_top, core_top]
fiber_bot = [core_bottom, outer_bot]
```

### 4. Convert Pixel Rows To Blender V

The Blender convention is:

```text
V = 0 at bottom
V = 1 at top
```

For an image of height `H`:

```text
core_v_min      = 1 - core_bottom_y / H
core_v_max      = 1 - core_top_y / H
fiber_bot_v_min = 1 - outer_bottom_y / H
fiber_top_v_max = 1 - outer_top_y / H
```

The metadata also keeps diagnostic inner boundaries:

```text
fiber_top_v_min = core_v_max
fiber_bot_v_max = core_v_min
```

The active Blender graph consumes:

```text
Arc 1 V Min <- core_v_min
Arc 1 V Max <- core_v_max
Arc 2 V Min <- fiber_bot_v_min
Arc 2 V Max <- fiber_top_v_max
```

### 5. U Scale For AI Images

The first AI attempt used the scanned-yarn auto fallback:

```text
texture_scale_u = core_v_span * 0.6
```

That made AI textures look stretched. The first explicit AI fix used dense
core height only:

```text
ARC1_V_AROUND_SPAN = 0.6
core_v_span = core_v_max - core_v_min
texture_scale_u = core_v_span / ARC1_V_AROUND_SPAN
```

That was better, but narrow-core frayed AI images could still look slightly
stretched because semi-transparent fibers occupy real visible width. The
current v2 rule uses opacity-weighted visible width:

```text
alpha_equivalent_width_px = sum((alpha / 255) ** 1.5) / image_width_px
core_only_u = core_height_px / (image_height_px * ARC1_V_AROUND_SPAN)
alpha_mass_u = alpha_equivalent_width_px / (image_height_px * ARC1_V_AROUND_SPAN)
texture_scale_u = min(max(core_only_u, alpha_mass_u), core_only_u * 2.0)
```

Because `texture_scale_u` is explicit and non-`1.0`, the backend marks it as
non-auto and pushes it directly to `Material N Texture Scale U`.

### 6. Physical Scale

The AI images do not provide trusted scanner DPI. We currently keep:

```text
dpi = 1600
scanner_pixels_per_bu = dpi * 39.3701
texture_world_width_m = image_width_px / dpi * 0.0254
```

This preserves compatibility with the existing contract. However,
`physical_scale.confidence` should remain `metadata_only` for AI images.

Future UI implementation should make this explicit: AI yarns have good
relative texture/V metadata, but their absolute physical size is not scan
calibrated unless the generator supplies real-world scale.

## Current Thresholds

| Parameter | Value | Purpose |
|---|---:|---|
| `CORE_ALPHA_THRESHOLD` | `224` | Find only very dense core pixels. |
| `CORE_DENSITY_FRACTION` | `0.95` | Keep central run near peak density. |
| `ARC2_ALPHA_THRESHOLD` | `5` | Include faint visible fibers. |
| `ARC2_ROW_DENSITY` | `0.02` | Require at least 2% row support to avoid isolated noise. |
| `ARC1_V_AROUND_SPAN` | `0.6` | Current graph core span used for U scaling. |

These are experimental and should be revisited with more AI batches.

## Diagnostics Required For Each Batch

For every batch, keep:

- raw source file list,
- original AI metadata snapshot,
- corrected `metadata.json` per yarn,
- overlay image showing old core, new core, and Arc 2 support,
- API listing of runtime assets,
- Blender socket readback,
- viewport screenshot after metadata push.

The first batch uses:

```text
runtime/ai_yarn_sanity/ai_yarn_v_band_overlay_after_arc2_fix.png
runtime/ai_yarn_sanity/blender_after_ai_arc2_v_band_fix.png
```
