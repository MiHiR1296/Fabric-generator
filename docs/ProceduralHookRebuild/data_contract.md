# Data Contract

## Hook Pattern Document

```jsonc
{
  "version": 1,
  "structureType": "hook",
  "structureFamily": "crochet_hook",
  "rowDirection": "alternating",
  "rows": 15,
  "columns": 21,
  "repeat": { "mode": "tile", "rows": 6, "columns": 6 },
  "stitchCodes": [[1, 0, 6]],
  "chainIds": [[0]],
  "courseIds": [[0]],
  "waleIds": [[0]],
  "chains": [
    { "id": 0, "materialSlot": 0, "direction": "vertical" }
  ],
  "stitchLegend": [
    {
      "code": 1,
      "symbol": "loop",
      "label": "Standard interlocking hook loop",
      "archetype": "standard_hook_loop",
      "supported": true
    }
  ],
  "gauge": {
    "unit": "bu",
    "density": 1,
    "openness": 0.2,
    "tension": 0.5
  },
  "source": {
    "kind": "generated",
    "access": "builtin",
    "title": "Starter hook structure"
  },
  "title": "Standard Hook 15x21",
  "sourceLabel": "Hook preset",
  "renderSettings": {}
}
```

Rules:

- `stitch_code=0` is empty/no stitch.
- `stitch_code=1` is the current standard interlocking hook archetype.
- Nonzero reserved codes are preserved as pattern intent and rendered with the
  standard V1 hook archetype until Blender gains native stitch shapes.
- `structureFamily` describes where the chart came from:
  `crochet_hook`, `knit_chart`, `machine_knit`, or `generic_loop_grid`.
- `rowDirection` records chart reading direction:
  `right_to_left`, `left_to_right`, `alternating`, or `in_the_round`.
- `repeat.mode="tile"` expands the supplied matrices to the final grid size.
- `chainIds` maps each cell to a continuous yarn chain.
- `courseIds` and `waleIds` are explicit future-facing knit/crochet
  continuity axes; defaults are row and column.
- `chains[].materialSlot` is zero-based and maps to Blender `Material 1..16`.
- `stitchLegend`, `gauge`, and `source` are preserved even when Blender V1
  falls back visually, so the frontend pattern library can grow without a
  later document redesign.
- Backend computes `chain_u_index` per active chain so sparse cells do not reset
  scanned-yarn travel.

## HookBuildSpec

The backend derives a `HookBuildSpec` from the normalized document before
Blender receives the sync script. This is the bridge between user intent and
generated structure.

```jsonc
{
  "version": 1,
  "buildMode": "generated_mesh_bridge_v1",
  "interpreter": "hook_pattern_document_to_generated_mesh",
  "frontendIntent": {
    "structureFamily": "crochet_hook",
    "rowDirection": "alternating",
    "repeat": null,
    "source": { "kind": "generated", "access": "builtin" }
  },
  "grid": {
    "rows": 15,
    "columns": 21,
    "activeCells": 315,
    "emptyCells": 0
  },
  "stitches": {
    "supportedCodes": [1],
    "unsupportedCodes": [],
    "fallbackCodes": {},
    "v1GeometryArchetype": "standard_interlocking_hook_loop"
  },
  "continuity": {
    "chainModel": "per_chain_active_cell_order",
    "uIndexAttribute": "chain_u_index",
    "sparseCellsDoNotResetU": true
  },
  "materials": {
    "maxSlots": 16,
    "usedSlots": [0]
  },
  "visualReference": {
    "role": "calibration_reference_only",
    "expectedObjectName": "HookVisualReference_PreV2"
  }
}
```

Rules:

- `HookBuildSpec` is generated by the backend, not authored by the frontend.
- It may be returned from `/api/blender/sync-hook` and
  `/api/blender/sync-hook-project` for debugging/readback.
- Unsupported nonzero stitch codes remain in the document and are listed in the
  build spec; V1 renders them with the standard hook loop until Blender gains
  native archetypes.
- The Pre-V2 setup is referenced only through `visualReference`; it is a
  silhouette calibration target, not an active production renderer.

## HookDraft_Live

The backend creates one face per hook cell and writes face attributes:

| Attribute | Type | Meaning |
|---|---|---|
| `stitch_code` | int | `0` empty, `1` standard hook |
| `chain_id` | int | chain id from the pattern, `-1` for empty |
| `chain_u_index` | int | active-cell order inside that chain, `-1` for empty |
| `chain_material_id` | int | zero-based material slot, `-1` for empty |
| `course_id` | int | course/row continuity id, `-1` for empty |
| `wale_id` | int | wale/column continuity id, `-1` for empty |

## Generated Hook Mesh

The live V2 bridge also writes the visible yarn mesh to `ProceduralHook`.
Geometry is constructed as continuous hook strips, not as one closed hook object
per cell. Empty cells split strips; dense rows remain connected across their
active spans. Generated geometry stores:

| Attribute | Domain | Meaning |
|---|---|---|
| `stitch_code_sampled` | face | active stitch archetype |
| `chain_id` | face | source yarn chain |
| `chain_u_index` | face | continuous U order inside the chain |
| `material_id` | face | one-based material id matching `Material N` |
| `u_along` | point | continuous yarn U coordinate |
| `v_around` | point | tube-around V coordinate |
| `uv_scaled` | point vector | texture coordinate consumed by yarn materials |
| `source_image_width_px` | face | material metadata placeholder |
| `texture_world_width_bu` | face | material metadata placeholder |

## Modifier Sockets

The hook sync path writes current controls by name when present. During the
pipeline bridge, the live output is the generated mesh on the object input so
frontend rows, columns, sparse masks, and material slots are visible. The
modifier sockets mirror the look controls used to generate that mesh.

- `Row`, `Columns`
- `Pattern Scale`, `Leg Width`, `Loop Height`, `Handle Scale`, `Leg Z Offset`
- `Half Tube Radius`, `Curve Resolution`, `Tube Resolution`
- `Texture Scale U`, `Texture Scale V`, `Texture Offset V`,
  `Texture Side Flatten`
- `Arc 1 V Padding`, `Seed`

The material path uses the same yarn metadata family as weave:

```text
Material N
Material N Image Width Px
Material N Texture Scale U
Material N Arc 1 V Min
Material N Arc 1 V Max
Material N Arc 2 V Min
Material N Arc 2 V Max
Scanner Pixels Per BU
```
