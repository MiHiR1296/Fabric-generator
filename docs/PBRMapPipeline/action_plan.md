# PBR Map Pipeline V1 Plan

Status: V1 implementation contract, updated 2026-06-04.

This plan replaces the earlier PBR draft. The old draft allowed missing maps
to render through inline/lazy fallback paths. That behavior is rejected for V1.
Every rendered yarn asset must have a fresh, complete PBR manifest and PBR map
set before the render/setup route starts.

## 1. V1 Rules

- No render-time PBR bake.
- No lazy bake safety net.
- No partial-map fallback.
- No legacy diffuse-only fallback for rendered assets.
- No tangent-space UV-layer surgery in `Parametric Weave knotty` for V1.
- No global switch from `Linear` to `Cubic` until Phase 0 records an A/B
  winner.

If an asset is missing PBR, stale against its source `rgba.png`, generated by
an incompatible generator major, missing PBR files, or missing required UDIM
tiles, the render/setup preflight fails with HTTP `409`.

## 2. Source Of Truth

Canonical runtime source:

```text
runtime/yarn_assets/<asset_id>/pbr/manifest.json
```

`asset.json.pbrMaps` is a validated reference/cache summary only. It is useful
for the UI and route payload construction, but it is not authoritative. The
consumer always validates the manifest and source file on disk before sending
the asset to Blender.

The live Blender baseline for geometry/material facts is recorded in:

```text
docs/PBRMapPipeline/live_blender_source_of_truth.md
```

Regenerate that doc whenever a phase ships, before any geometry-node graph
edit, and after any rebuild/save of `Codex_ParametricWeave.blend`.

## 4. Runtime Layout

Per yarn asset:

```text
runtime/yarn_assets/<asset_id>/
├── rgba.png
├── asset.json
├── cycles_tiled/
│   ├── rgba_1001.png
│   ├── rgba_1002.png
│   └── rgba_1003.png
└── pbr/
    ├── manifest.json
    ├── normal_height.png
    ├── roughness_specular.png
    ├── preview.png
    └── cycles_tiled/
        ├── normal_height_1001.png
        ├── normal_height_1002.png
        ├── roughness_specular_1001.png
        └── roughness_specular_1002.png
```

Packed maps:

```text
normal_height.png
  R = object-space normal X
  G = object-space normal Y
  B = object-space normal Z
  A = height
  colorspace = Non-Color

roughness_specular.png
  R = roughness
  G = Specular IOR Level
  B = 0
  A = 1
  colorspace = Non-Color
```

UDIM PBR tiles are required when the full-resolution PBR maps exceed the Cycles
image dimension cap. The PBR tile count must match the source-driven
expectation and every tile path recorded by the manifest must exist. PBR tile
generation overwrites old tiles on every bake so regenerated manifests cannot
point at stale UDIM files.

Version policy:

```text
generator_version = yarn_pbr_v<MAJOR>.<MINOR>

MAJOR mismatch:
  invalidates the bake and returns 409.

MINOR mismatch:
  compatible by default. No automatic rebake required.
```

Preflight also compares `source_sha256` against the current source `rgba.png`.
Any hash mismatch means the bake is stale and must be regenerated.

## 6. Bake Algorithm

Input is the canonical full-resolution `rgba.png`.

1. Convert RGB to luminance without multiplying by raw alpha.
2. Build alpha support from `alpha > alpha_support_threshold`.
3. Suppress alpha-boundary phantom normals with vertical edge-extend:
   for each column, find the alpha-supported rows, fill rows above the support
   with the first visible row luminance, and fill rows below the support with
   the last visible row luminance. Columns with no support use the global
   supported-luma median.
4. Compute Sobel gradients from the filled luminance.
5. Build object-space normals:

```text
nx = -gx * normal_strength
ny = -gy * normal_strength
nz = 1
normalize(nx, ny, nz)
encode RGB = normal * 0.5 + 0.5
```

6. Write transparent/outside-support pixels as neutral:

```text
normal = (128, 128, 255)
height = midpoint
roughness = high
specular_ior_level = 0
```

7. Save `normal_height.png`, `roughness_specular.png`, `preview.png`, and
   `manifest.json`.
8. If needed, split both packed maps into matching UDIM tiles.

The generator stores per-asset bake options and consumer defaults in the
manifest so yarn-specific tuning survives render sessions. Environment
overrides are allowed only for diagnostics, not as hidden fallback behavior.

## 7. Import And Migration Flow

Asset import is transactional:

```text
copy/synthesize rgba.png
create source RGBA UDIM tiles when needed
bake PBR packed maps
validate manifest and packed maps
persist asset.json with pbrMaps reference
```

If any step fails, the partially imported asset directory is deleted.

Explicit recovery endpoints:

```text
POST /api/yarn-assets/<asset_id>/regenerate-pbr
  Re-bakes one existing asset from its current rgba.png.

POST /api/yarn-assets/migrate-pbr
  Starts an async bulk migration job.
  Body may include { "assetIds": ["..."] } or omit it for all ready assets.

GET /api/yarn-assets/migrate-pbr/<job_id>
  Returns job status, totals, completed ids, failed ids, and progress.
```

Bake points are import, regenerate, and migrate only. Render routes never
create or repair PBR files.

## 8. Render/API Preflight

The following routes validate PBR before Blender setup/render:

```text
POST /api/blender/render-project
POST /api/blender/render-project-tiles
POST /api/blender/push-bandmeta
POST /api/blender/push-project-bandmeta
```

Failure returns HTTP `409` with this direct JSON body:

```json
{
  "asset_id": "a83a49c70af0",
  "asset_label": "Greyrescan07",
  "missing_maps": ["pbr/manifest.json"],
  "stale_reason": "missing_pbr_manifest",
  "remediation": "POST /api/yarn-assets/a83a49c70af0/regenerate-pbr"
}
```

The frontend recovery path should show the asset label, missing/stale reason,
and a re-import/regenerate button on the yarn library row. Bulk migration
should be available for legacy libraries.

## 9. Blender Material Plan

Existing diffuse/alpha behavior remains intact:

```text
RGBA diffuse -> Principled BSDF Base Color
RGBA alpha   -> Principled BSDF Alpha
uv_scaled    -> existing material vector path
```

New V1 PBR nodes:

```text
FabricStudioNormalHeightNode
  ShaderNodeTexImage, Non-Color, normal_height packed image/UDIM

FabricStudioRoughnessSpecularNode
  ShaderNodeTexImage, Non-Color, roughness_specular packed image/UDIM

FabricStudioObjectNormalMap
  ShaderNodeNormalMap
  Space = OBJECT
  Strength = manifest consumer_defaults.normal_strength
  Default = 0.1

FabricStudioHeightBump
  ShaderNodeBump
  Strength = manifest consumer_defaults.bump_strength
  Default = 1.0
  Distance = manifest consumer_defaults.bump_distance_bu

FabricStudioRoughnessSpecularSplit
  ShaderNodeSeparateColor
```

Required links:

```text
raw RGBA RGB       -> Principled BSDF Base Color
raw RGBA Alpha     -> Principled BSDF Alpha

normal_height RGB   -> Object Normal Map Color
Object Normal       -> Bump Normal
normal_height Alpha -> Bump Height
Bump Normal         -> Principled BSDF Normal

roughness_specular R -> Principled BSDF Roughness
roughness_specular G -> Principled BSDF Specular IOR Level
```

The material setup fails if PBR files, source hash, generator major, UDIM
tile count, or manifest validation do not match. It does not silently swap to
diffuse-only shading.

## 10. Object-Space Normal Decision

The live evaluated mesh has `uv_scaled` as a POINT-domain `FLOAT2` attribute
and no UV layers. Blender tangent-space normal maps need a real corner-domain
UV layer to derive the tangent basis.

V1 therefore uses object-space normal maps. This avoids changing the
`Parametric Weave knotty` geometry-node graph, which is load-bearing and
already contains the approved mapping baseline.

Deferred options:

```text
Tangent-space mode with generated corner UV layer.
Tangent-space mode with POINT -> CORNER uv_scaled conversion graph.
Configurable object/tangent dual mode.
```

Only revisit those options if Phase 0 proves object-space unacceptable on the
active asset and at least one additional yarn class.

## 11. Interpolation Decision

Backend generated render scripts still default to:

```text
WEAVE_TEXTURE_INTERPOLATION=Linear
```

The live active material for `a83a49c70af0` currently has diffuse interpolation
set to `Cubic` and alpha interpolation set to `Linear`. V1 does not change the
global default from the plan alone.

Phase 0 must render a baked-PBR A/B:

```text
Linear vs Cubic on the same active asset, same camera, same render settings.
Record the winner in live_blender_source_of_truth.md.
Only then change the default if the evidence supports it.
```

## 12. Cleanup

Default:

```text
WEAVE_PRUNE_ORPHAN_MATERIALS=1
```

Debug override:

```text
WEAVE_PRUNE_ORPHAN_MATERIALS=0
```

Generated material cleanup may remove a material only when all predicates are
true:

1. Name matches `^FabricStudioMaterial_[0-9]{2}_[A-Za-z0-9_]+$`.
2. `users == 0`.
3. `use_fake_user == false`.
4. No object material slot references it.
5. No modifier input references it.
6. Its asset id is not in the current render/setup asset set.
7. It is not in the preview-active protected material set.

After material cleanup, zero-user generated FabricStudio image datablocks may
also be removed.

## 13. Test Plan

Generator tests:

- Flat luminance.
- Horizontal/vertical gradients.
- Fully transparent image.
- Alpha-boundary vertical edge-extend.
- Packed channel correctness.
- Source SHA-256 mismatch.
- Generator version major mismatch.
- Wide source image producing PBR UDIM tiles.
- Active asset `a83a49c70af0` map inspection in Phase 0.

Import/API tests:

- Complete transaction succeeds and writes `pbrMaps`.
- Bake failure deletes partial asset.
- Partial PBR fails preflight.
- Source hash mismatch fails preflight.
- Single regenerate endpoint.
- Bulk migrate endpoint and job progress.
- Render/setup `409` response shape.
- No render-time bake calls.

Blender script tests:

- Object-space `ShaderNodeNormalMap`.
- Packed channel splits.
- Exact Bump chain.
- `Specular IOR Level` socket wiring.
- Non-Color packed map image datablocks.
- Strict cleanup predicates.

## 14. Phase 0 Visual Acceptance

Before approving the bake algorithm as visually ready:

1. Bake the active asset `a83a49c70af0`.
2. Inspect `pbr/normal_height.png`.
3. Confirm the normal RGB is mostly purple/blue with red/green modulation only
   in the dense fiber band.
4. Confirm no strong red/green bands appear at the transparent alpha boundary.
5. Compare render output with `WEAVE_TEXTURE_INTERPOLATION=Linear` and `Cubic`.
6. Record the chosen interpolation default in
   `live_blender_source_of_truth.md`.

If alpha boundary bands are visible, the vertical edge-extend fill is broken
or insufficient and must be fixed before proceeding.

## 15. Disk And Memory Risk

Unpacked separate normal/height/roughness/specular maps would add too many
files and image datablocks at library scale. V1 uses the existing RGBA diffuse
asset plus two RGBA packed PBR images:

```text
source RGBA diffuse -> existing image/UDIM
normal + height       -> one RGBA image
roughness + specular  -> one RGBA image
```

This avoids the noisy cleaned-BaseColor branch and avoids four separate
non-color map files. Large libraries still need storage monitoring because
UDIM tiles can multiply per-asset size.
