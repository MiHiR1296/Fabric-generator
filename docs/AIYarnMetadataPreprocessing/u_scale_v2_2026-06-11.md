# U Scale V2 - 2026-06-11

This note records the stricter AI U-scale retry across all imported
AI-generated yarns.

## Reason

The first AI pass fixed the worst default mapping issue by writing an explicit
`blender.texture_scale_u`, but the value was still based only on the strict
dense core:

```text
texture_scale_u = core_v_span / 0.6
```

That underestimates AI images where the visible yarn is wider than the dense
core because semi-transparent generated fibers and frays occupy real visual
width. The result can still read as slight U stretch, especially on narrow-core
frayed sources.

## New Rule

The V bands are still detected the same way:

```text
Arc 1 core:
  alpha > 224
  row density >= 95% of peak

Arc 2 support:
  alpha > 5
  row density >= 2%
  contiguous support around the core
```

The U scale now uses opacity-weighted visible width:

```text
alpha_equivalent_width_px = sum((alpha / 255) ** 1.5) / image_width_px

core_only_u = core_height_px / (image_height_px * 0.6)
alpha_mass_u = alpha_equivalent_width_px / (image_height_px * 0.6)

texture_scale_u = min(max(core_only_u, alpha_mass_u), core_only_u * 2.0)
```

Why `alpha ** 1.5`:

- fully opaque core counts strongly,
- real semi-transparent fibers still count,
- faint isolated wisps are downweighted,
- extreme AI halos cannot push the repeat beyond a 2x boost.

Metadata strategy:

```text
blender.texture_scale_u_strategy = "ai_alpha_mass_equivalent_width_v2"
```


Backend endpoints:

```text
POST /api/yarn/ai/import
POST /api/yarn/ai/refresh-u-scale
```

Frontend:

```text
Step 1 -> Upload view -> AI generated yarn
```

The AI upload path accepts image files plus optional JSON files. It writes
corrected metadata, saves the result to `yarn_library`, imports it into runtime
assets, and refreshes the existing Step 1 library/runtime lists.
